# Phase 1 Data Model: OryxOS Core Runtime

## Modeling Principles

- Domain models live in `oryxos-core`; persistence entities stay in `oryxos-storage`.
- Public identifiers are opaque strings or UUIDs and are never derived from secrets.
- All timestamps are UTC instants in storage and ISO 8601 strings at API boundaries.
- Session messages are an ordered aggregate. Tool and LLM audits are independently queryable records.
- Agent definitions are workspace documents. Long-term memory is accessed only through `LongTermMemoryStore` and may be backed by workspace Markdown, SQLite, or self-hosted Mem0.
- `ReActLoop` and `PromptBuilder` access Session, long-term, and future episodic memory only through the unified `MemoryService` façade.

## 1. AgentDefinition

Represents one `.oryxos/agents/<name>/` directory.

| Field | Type | Rules |
|---|---|---|
| `name` | string | Directory name; unique in one workspace; matches `^[a-zA-Z0-9][a-zA-Z0-9_-]{0,63}$`. |
| `agentFile` | path | Required normalized path to `AGENT.md` under the Agent directory. |
| `body` | string | Markdown system instruction after frontmatter; non-empty. |
| `profile` | Profile | Derived from frontmatter; never edited as a separate file. |
| `skillsDirectory` | path? | Optional `skills/` child directory. |
| `scriptsDirectory` | path? | Optional `scripts/` child directory. |
| `referenceFile` | path? | Optional `REFERENCE.md`. |
| `loadStatus` | enum | `VALID` or `INVALID`. |
| `validationErrors` | list<string> | Populated only for invalid definitions. |

Invalid definitions are reported and excluded from the Profile registry without preventing other Agents or the application from loading.

## 2. Profile

Runtime configuration derived from `AGENT.md` frontmatter.

| Field | Type | Rules |
|---|---|---|
| `name` | string | Same as Agent directory name. |
| `provider` | string | Required key in the explicit Provider map. |
| `model` | string? | Optional Provider-specific model override. |
| `tools` | ordered set<string> | Names available to this Agent; every name must resolve in `ToolRegistry`. |
| `channels` | ordered set<string> | Enabled trigger/output channels. |
| `notifyTarget` | string? | Logical notification target; secrets are referenced indirectly. |
| `schedules` | list<ScheduleDefinition> | Optional cron triggers. |
| `maxIterations` | integer | Optional override, range 1–10; default 10. |
| `temperature` | decimal? | Optional Provider setting within Provider-supported bounds. |

## 3. ScheduleDefinition

Configuration value loaded from Agent frontmatter; not persisted as a database row in the core stage.

| Field | Type | Rules |
|---|---|---|
| `id` | string | Unique within one Agent. |
| `cron` | string | Valid Spring cron expression. |
| `zoneId` | string | Valid IANA time zone; defaults to configured workspace zone. |
| `prompt` | string | Non-empty trigger message. |
| `enabled` | boolean | Defaults to true. |

Runtime state contains one keyed `ReentrantLock` per `(agentName, scheduleId)`. If the lock is held, that occurrence is skipped and logged. Occurrences missed while the service is stopped are not replayed.

## 4. Session

Durable ordered conversation and audit correlation root.

| Field | Storage | Type | Rules |
|---|---|---|---|
| `sessionId` | `session_id` | UUID/string | Primary key, generated by service. |
| `profileName` | `profile_name` | string | Required Agent/Profile name. |
| `channel` | `channel` | string | Required trigger source, e.g. `cli`, `api`, `scheduler`. |
| `userId` | `user_id` | string | Required caller identity; scheduler uses `scheduler`. |
| `messages` | `messages_json` | list<Message> | Ordered JSON array. |
| `status` | `status` | enum | `ACTIVE` or `ARCHIVED`. |
| `createdAt` | `created_at` | instant | Set once. |
| `lastActiveAt` | `last_active_at` | instant | Updated after each accepted append. |
| `archivedAt` | `archived_at` | instant? | Required only when status is `ARCHIVED`. |
| `version` | `version` | long | Optimistic persistence guard; does not replace service-level Session serialization. |

### Session Identity

Interactive lookup uses `(profileName, channel, userId)` to find an active Session when a caller requests reuse. Explicit Session API operations use `sessionId`. Stateless Agent invocation creates a new internal Session.

### State Transitions

```text
create --> ACTIVE --> ARCHIVED
              |
              `--> append ordered messages

ARCHIVED --message--> rejected (409 Conflict)
```

Archive is idempotent. Archived Session content remains queryable until an administrator explicitly removes workspace data.

### Session Detail Projection

`GET /api/v1/sessions/{id}` returns a read projection rather than introducing a
separate audit endpoint. The projection contains the bounded Session message
history plus two independently queryable audit collections:

| Field | Type | Rules |
|---|---|---|
| `llmCalls` | list<LlmCall> | Ordered by `(startedAt, id)` ascending for the requested audit page. |
| `toolInvocations` | list<ToolInvocation> | Ordered by `(startedAt, id)` ascending for the requested audit page. |
| `llmCallsPage` | PageMetadata | `llmOffset`, `llmLimit`, and total LLM Call rows linked to the Session. |
| `toolInvocationsPage` | PageMetadata | `toolOffset`, `toolLimit`, and total Tool Invocation rows linked to the Session. |

Clients page the two audit collections independently with
`llmOffset`/`llmLimit` and `toolOffset`/`toolLimit`. Each page reports its own
offset, limit, and total, so every persisted attempt remains retrievable even
when one collection grows faster than the other. Creation and archive responses
continue to return the base Session representation.

## 5. Message

Value object embedded in `Session.messages`.

| Field | Type | Rules |
|---|---|---|
| `messageId` | UUID/string | Unique within a Session. |
| `sequence` | long | Strictly increasing within a Session. |
| `role` | enum | `SYSTEM`, `USER`, `ASSISTANT`, or `TOOL`. |
| `content` | string | Required; a submitted user message is at most 32 KiB. |
| `toolCallId` | string? | Required for Tool-result correlation where applicable. |
| `toolName` | string? | Present for Tool call/result messages. |
| `createdAt` | instant | Assigned when appended. |

Prompt construction injects at most the latest 20 history messages after Agent/bootstrap/memory context. Session API responses return at most 100 messages.

## 6. ToolDefinition

Runtime registry entry, not a database entity.

| Field | Type | Rules |
|---|---|---|
| `name` | string | Globally unique registry key. |
| `description` | string | Human/model-readable behavior statement. |
| `inputSchema` | JSON Schema | Valid object schema. |
| `origin` | enum | `BUILT_IN`, `MCP`, or `JAVA_PLUGIN`. |
| `source` | string | Built-in package, MCP server name, or plugin bean identity. |

Duplicate names fail registry initialization unless an explicit deterministic override policy is configured; the core default is fail-fast.

## 7. ToolResult

Normalized Tool execution result.

| Field | Type | Rules |
|---|---|---|
| `success` | boolean | True only when execution completed successfully. |
| `content` | string? | Model-visible output; bounded/redacted before persistence and prompt injection. |
| `error` | string? | Safe error description when unsuccessful. |
| `retryable` | boolean | Whether the ReAct loop may retry within its remaining iteration budget. |

`success=true` requires `error=null`. `success=false` requires a non-empty `error`.

## 8. ToolInvocation

Durable audit row for every attempted Tool execution, including validation or Sandbox rejection.

| Field | Storage | Type | Rules |
|---|---|---|---|
| `id` | `id` | UUID/string | Primary key. |
| `sessionId` | `session_id` | UUID/string | Indexed foreign-key correlation to Session. |
| `toolName` | `tool_name` | string | Requested registry name. |
| `argumentsJson` | `arguments_json` | JSON string | Redacted validated/supplied arguments; secrets omitted. |
| `success` | `success` | boolean | False for validation, policy, transport, or Tool failure. |
| `resultSummary` | `result_summary` | string? | Bounded safe summary. |
| `errorCode` | `error_code` | string? | Stable category such as `INVALID_ARGUMENT`, `SANDBOX_DENIED`, `TIMEOUT`, `TOOL_ERROR`. |
| `errorMessage` | `error_message` | string? | Redacted safe detail. |
| `retryable` | `retryable` | boolean | Normalized Tool retry advice. |
| `startedAt` | `started_at` | instant | Required. |
| `completedAt` | `completed_at` | instant | Required. |
| `durationMs` | `duration_ms` | long | Non-negative. |

Indexes: `(session_id, started_at)` and `(tool_name, started_at)`.

| `errorCode` | `error_code` | string? | Stable failure category. |
| `errorMessage` | `error_message` | string? | Redacted safe detail. |

Raw API keys, authorization headers, and unredacted secret-bearing prompts/results must never be stored.

## 10. MemoryService and MemoryContext

`MemoryService` is the only memory contract visible to `ReActLoop` and `PromptBuilder`.

```java
public interface MemoryService {
    MemoryContext loadContext(String sessionId, Profile profile);
    Session appendSessionMessage(String sessionId, Message message);
    void appendLongTerm(String content, MemoryScope scope);
    LongTermMemoryView recallLongTerm(String keyword, int maxChars);
}
```

`ReActLoop` uses `appendSessionMessage` for every generated Assistant and Tool
message. The concrete façade delegates that operation to the Session layer, so
the loop preserves execution order without receiving a `SessionStore` or other
persistence port.

The concrete façade delegates:

| Layer | Core-stage source | Behavior |
|---|---|---|
| Session memory | `SessionManager` → SQLite Session storage | Ordered, bounded history for the current Session. |
| Long-term memory | Selected `LongTermMemoryStore` | Core plus bounded archival memory and keyword recall. |
| Episodic memory | Extension slot | Empty in the core stage; no episodic retrieval implementation is claimed. |

`MemoryContext` is an immutable value returned in one call:

| Field | Type | Rules |
|---|---|---|
| `sessionMessages` | ordered list<Message> | Latest bounded messages in Session order. |
| `coreMemory` | markdown/text | Complete core-scope long-term memory. |
| `archivalMemory` | markdown/text | Deterministically bounded archival memory. |
| `episodicMemory` | list | Empty in the core stage. |
| `loadedAt` | instant | Time the uncached view was assembled. |

Neither ReAct nor PromptBuilder may directly call `SessionStore`, read `MEMORY.md`, query `memory_entries`, or call Mem0.

## 11. LongTermMemoryStore

Backend contract owned by the Memory module:

```java
public interface LongTermMemoryStore {
    void append(String content, MemoryScope scope);
    LongTermMemoryView load();
    LongTermMemoryView recallByKeyword(String keyword);
}
```

The shared append contract trims surrounding whitespace, rejects empty content
and content larger than 32 KiB, and treats an exact duplicate in the same scope
as an idempotent append. Backend-specific consolidation is allowed only when the
shared view still exposes the fact once. These rules apply identically to
Markdown, SQLite, and Mem0, including concurrent append serialization.

`MemoryScope` is `CORE` or `ARCHIVAL`, defaulting to `ARCHIVAL` at the Tool boundary.

All implementations obey the same contract:

1. No caching; each operation reads its authoritative backend.
2. Core memory is always loaded completely.
3. Deterministic truncation applies only to archival memory.
4. The caller explicitly selects the scope.
5. Recall uses the contract's keyword semantics; a backend may provide stronger semantic matching without changing callers.
6. Writes are serialized, and reads observe appends completed before the read began.

Configured implementations:

| `memory.backend` | Implementation | Authoritative storage |
|---|---|---|
| `markdown` | `MarkdownMemoryStore` | `.oryxos/memory/MEMORY.md` |
| `sqlite` | `SqliteMemoryStore` | `memory_entries` table in `.oryxos/oryxos.db` |
| `mem0` | `Mem0MemoryStore` | Self-hosted Mem0 REST service |

Unknown backend values fail startup with a safe configuration error. Credentials and authorization headers for Mem0 are never stored in memory entries or logs.

## 12. LongTermMemoryDocument

Logical representation of `.oryxos/memory/MEMORY.md`.

| Field | Type | Rules |
|---|---|---|
| `core` | markdown | Protected stable facts/preferences; always considered first for prompt injection. |
| `archival` | ordered markdown entries | Append-oriented observations. |
| `lastModifiedAt` | instant | Derived from the file. |

The Markdown store serializes writes. Prompt injection applies deterministic character/token limits, preserves the core section first, and truncates archival content from oldest to newest as specified by implementation configuration.

## 13. MemoryEntry

SQLite representation used only when `memory.backend=sqlite`.

| Field | Storage | Type | Rules |
|---|---|---|---|
| `id` | `id` | UUID/string | Primary key. |
| `scope` | `scope` | enum | `CORE` or `ARCHIVAL`; indexed. |
| `content` | `content` | text | Required memory content. |
| `createdAt` | `created_at` | instant | Required; used for deterministic ordering. |

Indexes: `(scope, created_at)`. The table is initialized with the same explicit schema mechanism as Session and audit tables.

## 14. ApiResponse

Common REST envelope.

| Field | Type | Rules |
|---|---|---|
| `code` | string | Stable application code, `OK` on success. |
| `message` | string | Human-readable summary. |
| `data` | any/null | Endpoint payload. |
| `timestamp` | ISO 8601 instant | Response creation time. |

HTTP status remains authoritative; `code` provides stable client handling.

## 15. Persistence Relationships

```text
Session 1 ─────── * ToolInvocation
   |
   `───────────── * LlmCall

AgentDefinition 1 ───── 1 Profile
AgentDefinition 1 ───── * ScheduleDefinition  (workspace configuration only)

MemoryService
├── SessionManager ───── Session
└── LongTermMemoryStore
    ├── MarkdownMemoryStore ───── MEMORY.md
    ├── SqliteMemoryStore ─────── memory_entries
    └── Mem0MemoryStore ───────── self-hosted Mem0
```

Foreign-key deletion is not exposed by core APIs. The Session archive operation changes state and retains all audit rows.
